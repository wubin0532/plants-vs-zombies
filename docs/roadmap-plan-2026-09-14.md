# 后续优化与僵尸智能计划（2026-09-14）

来源：设计者视角评估（性能实测 + 代码走查）与"僵尸智能化"讨论。本文档只做计划，不含实现。
前置状态：114 项测试全绿、构建通过；三批体验优化与方案 B 已完成并推送。

统一验收：每项完成后 `npm test` 全绿、`npm run build` 通过；涉及玩法的项需在 tests/ 补回归测试；UI 变更用 Playwright 截图验证。

## 优化批 1：资源与加载（性能，实测驱动）

实测：dist/assets 24MB；背景 PNG 单张约 2.2MB；phaser-*.js 1.2MB 静态引入。

1. 图片转 WebP（背景 7.5MB、动作图集 6.8MB、portraits 3.1MB、fx 976K，quality≈80，预期总量降到 ~2MB）
   - 涉及：scripts/prepare-assets.mjs / prepare-motion.mjs 输出 WebP；src/game/art.ts 与 scene.ts preload 的后缀引用；确认 Phaser WebP 支持。
   - 验收：dist/assets 总量 < 4MB；页面视觉回归截图对比。
2. Phaser 按需加载：主页不加载 phaser 包，进入战斗时动态 import
   - 涉及：src/game/scene.ts 改为惰性加载入口，App.vue start() 内 await。
   - 验收：首页首屏 JS ≤ 200KB（gzip 前约 500KB），战斗功能无回归。

## 优化批 2：小而确定的修复

3. 2x 加速时音乐节奏翻倍问题：audio.update 改用真实时钟，或加速时切高压乐段（可当特性）。
4. 消息通道加优先级队列：alert 级（强敌/告急）不被 info 级（黄金僵尸/波次提示）覆盖，info 排队。
   - 涉及：engine.ts say()/message/messageUntil 改为小队列；App.vue stats.message 读取队首。
5. R 键重开加防误触：战斗中需二次确认（3 秒内按两次 R 生效，第一次给提示）。
6. 引擎热点：植物攻击段的 `zombies.filter` 提升到 step 顶部每步只算一次存活敌方列表。
   - 验收：45 植物 × 120 僵尸压测脚本（output/playwright/motion-performance.cjs 模式）P95 不劣化。

## 优化批 3：玩法增强

7. 选卡推荐：选关页按本关敌人列表，用图鉴"对策"数据给克制卡加"推荐"角标。
8. 连杀奖励：3 秒内击杀 ≥4 只僵尸掉 25 阳光 token，配合提示音与特效。
9. 动态难度保护：同一关连输 2 次，结算页提供"切换休闲难度"一键按钮。
10. 地图格子显示每关最佳用时（scores 已记录）与星级并列。

## 优化批 4：锦上添花

11. 关卡内随机事件：每局 1 次"阳光雨"（10 秒阳光翻倍）或"寒风"（全场减速 5 秒），engine 计时器 + say 提示。
12. 新手教程气泡指向具体 UI 元素（种子栏、阳光计数器）。
13. 失败结算页加"调整难度"入口（与 9 联动）。
14. 图鉴试玩沙盒：图鉴卡片加"试玩"，进入一个无敌方小场景演示植物攻击。
15. 存档版本化：version 2 + 迁移函数，保留宽松校验兜底。
16. 低性能验证：Playwright CPU 4x throttle + 低分辨率跑 45×120 场景，记录帧间隔。
17. campaign 增强：每关至少一轮跑到高波次（≥10 波），覆盖狂暴精英与扶梯/矿工等特殊组合的回归。

## 导演系统（僵尸智能）

目标：僵尸从"静态剧本"升级为"感知局势的导演"。所有决策走 engine.random 种子随机，保证可复现。

### 一期：弱行加权出怪（智能感立刻可见）

- 防线评估：每波开始前对每行计算防御强度分（植物秒伤合计 + 坚果剩余生命 + 减速/地刺加成 - 该行存活僵尸总生命）。
- 出怪行选择从纯随机改为加权随机：约 60% 压最弱两行、30% 随机、10% 强行（保留不可预测性）。
- 涉及：engine.ts spawn() 的行选择（row === undefined 分支）+ 新增行强度评估函数。
- 测试：模拟"单侧重防"与"均衡防御"两种局面，断言前者弱行承受出怪量显著更高；campaign 50 关回归。
- 边界：前 3 关与休闲难度只用一半倾斜强度。

### 二期：点数预算 + 兵种克制（完整导演）

- makeWaves 静态课表改为逐波动态决策：每波有预算点数（随波次/难度增长），普通 1 点、路障 2 点、巨人/橄榄球 6 点等，导演在预算内"购买"阵容。
- 克制表（权重加成，命中防线特征时生效）：
  - 坚果+射手铁桶阵 → 撑杆/海豚/跳跳/扶梯/矿工
  - 高坚果硬顶 → 气球/投石车
  - 植物密集堆叠 → 玩偶匣/巨人
  - 单行重兵 → 蹦极偷核心
  - 水路不设防 → 潜水/海豚
  - 玩家阳光囤积（经济碾压）→ 下波预算加码
- 特殊兵种冷却：巨人出场后 2 波内不再出。
- 与既有机制的关系：狂暴精英（第 10 波起）是单体强化，继续叠加；关卡敌人列表仍是可用兵种池上限。
- 涉及：difficulty.ts makeWaves 重构为 director 模块（保留 exported 签名或迁移调用点）、engine.ts 出怪循环。
- 测试：克制触发频率、预算上限、冷却间隔、确定性（同种子同结果）；upgrade.test.ts 既有不变式（首波/末波时间、排序、难度排序）保持。

### 三期：橡筋难度 + 总攻预告

- 橡筋约束：玩家丢车或行被破 → 下一波预算减档；满阳光零损失 → 加档。
- 总攻预告：旗波集中压弱行前 3-5 秒 alert 提示"僵尸主力瞄准了第 X 行！"。
- 涉及：engine.ts 波次决策点、say 警示通道（依赖优化批 2 的消息队列）。

### 导演系统统一边界

- 可预测性：智能不等于偷袭，大招必有预告。
- 新手保护：前 3 关与休闲难度降级。
- 确定性：全部走种子随机数。
- 性能：评估每波一次，开销可忽略。

## 建议执行顺序

优化批 1 → 导演一期 → 优化批 2 → 导演二期 → 优化批 3 → 导演三期 → 优化批 4。

理由：性能问题影响所有玩家立即体验；导演一期性价比最高；消息队列（批 2 第 4 项）是导演三期的前置。
