# 动画、僵尸 AI 与性能复查

检查基线：Kimi 提交 `10d7802`。工作包括已有功能复查、动画补充、小推车重绘和渲染性能优化。基线 143 项测试通过；本轮新增动作和 AI 回归后，161 项测试通过。

## Kimi 功能复查

WebP 素材、Phaser 按需加载、导演系统三期、随机事件、存档版本 2 迁移等已有实现，相关自动测试通过。主页构建入口约 171 KB，Phaser 保持独立延迟加载。没有将自动测试通过等同于全关卡人工平衡验收。

修复图鉴试玩的两个问题：目标原先随机落在其他行，短时间内可能看不到植物发射；试玩异步加载期间关闭窗口，旧加载仍可能创建游戏实例。现在目标固定在植物所在行，关闭操作会使旧请求失效。主战场也加入重复开局保护和异步返回校验。

浏览器验证：模拟 600 毫秒模块加载延迟后立即关闭试玩，最终画布数为 0、试玩实例为空；正常豌豆试玩的植物和目标均在第 3 行，检测到实际发射。并发调用两次开局，最终仅有 1 个画布；开局期间返回主页后，画布数归零。

## 动画与小推车

- 舞王和伴舞新增摆臂、踏步和重心变化；舞王另有 8 帧召唤动作。召唤在 0.45 秒结算一次，冻结暂停、减速延长动作，伴舞继承阵营和朝向。
- 21 种植物使用共享原纹理的根部／上部分区。根部保持稳定，上部有待机摆动、蓄力、发射回弹或投掷动作；休眠停止上部动作。
- 橄榄球、小鬼、雪人有敏捷姿态，跳跳和漂浮类有独立运动反馈。行走到啃咬的姿态在 0.16 秒内收回；漂浮高度纳入渲染插值，跳跳起跳继承原高度，死亡保留起始倾角。
- 程序烘焙图集加透明边距，避免摆臂、迈腿越界。浏览器逐帧检查舞王全部 20 帧：均非空，边缘无不透明像素。
- 小推车改为红色车身、金属发动机、橡胶轮胎和把手，显示宽度为 82 像素；备用车为 57 像素。四帧车轮纹理只生成一次。
- 出动时从停车位置向右加速驶出画面；出动反馈独立于普通特效数量限制，130 个其他特效下仍能显示，结束后清理。保留原有整行清屏规则，移动属于视觉反馈，不宣称已实现逐个碰撞碾压。

素材方式：在现有 WebP 上做分层程序动画，并用 Canvas 程序绘制推车纹理；没有新增 AI 生图素材，也没有将这些动画描述为全部独立手绘序列。其余角色更精细的肢体拆分和动作衔接仍可继续打磨。

## AI 问题与修复

| 问题 | 修复与验证 |
| --- | --- |
| 总攻预告与实际选路脱节 | 为对应波次保存预告行，适合进入该行的兵种以 60% 概率优先选择；泳池总攻预告选择陆地行。测试实际出怪集中到预告行。 |
| 水生僵尸忽略指定水路，双水路弱行选择不起作用 | 保留合法指定水路，自主选路只在水路中评估；两条候选水路时弱行区间缩为一条。测试无水陆越界且弱水路出怪更多。 |
| 伴舞可能被召唤进水池 | 舞王跳过相邻水格，保留可用陆地位置。 |
| 继续攻击已死亡植物 | 近战和投石车目标过滤死亡植物；回归验证跳过死亡南瓜、攻击存活的下层植物。 |
| 减速动作和攻击节奏不同步 | 移动、动作、技能进度和攻击冷却使用相同减速比例；冻结仍保持动作阶段。 |
| 魅惑特殊僵尸可能误伤植物 | 魅惑玩偶匣爆炸攻击敌方僵尸；魅惑蹦极／投石车不再执行伤害植物的特殊分支。 |
| 特殊技能移除植物未计入受挫保护 | 蹦极和玩偶匣破坏计入植物损失；铲除和主动消耗不计入。 |
| 防线评分计入死亡、休眠植物的火力 | 忽略死亡植物和休眠火力；克制评估同样过滤休眠射手。 |
| 备用车仍在时提示“失去最后保护” | 提示明确区分尚有备用车和无剩余保护。 |

保留原来的预算上限、兵种池、特殊兵种冷却、休闲／前三关保护及种子确定性。相关导演测试、50 关自动策略测试继续通过。

## 渲染优化

原项目已使用 `Phaser.AUTO`，支持 WebGL 时本来就会使用 GPU。本轮保留 Canvas 降级，添加高性能 GPU 偏好提示，并关闭 WebGL 上下文多重采样，保留纹理线性过滤。

迷雾和地块改为渲染纹理缓存，仅状态变化时更新；角色静态深度不再重复触发全场排序；程序僵尸图集按首次出现生成；复用插值记录和存活对象集合，避免特效切片数组。

迷雾像素实测：正常／吹散／路灯照明／恢复的 alpha 分别为 168／0／0／168；连续 10 次状态不变的更新不重画缓存。植物回弹前后根部位置、角度和尺寸一致。

## 验收边界

WebGL 与禁用 WebGL 后的 Canvas 降级均已通过渲染检查：角色动作、迷雾缓存和推车显示／清理正常。Chromium 桌面与模拟 844 × 390 横屏已检查。横屏实测画布位于视口内，菜单可见。未完成真实 iPhone／Android、Safari 长时运行和 50 关人工通关；导演调整可能改变部分关卡节奏，仍需实际试玩校准。

生产构建通过，Phaser 独立大代码块仍有 Vite 体积提示。它只在战场／试玩启动时加载，本轮没有引入新的外部运行依赖。

## 性能实测

Chromium，Apple M4，实际适配器为 `ANGLE Metal Renderer: Apple M4`，WebGL 渲染器类型为 2。视口 1200 × 900，内部画布 1200 × 690，迷雾关卡，45 株植物、120 只僵尸，高特效。对比基线为独立临时目录中的 `10d7802`，没有回退工作区文件。

压测提高角色生命、关闭自动波次和跳跳越障，保证采样结束仍为 45／120 个实体；它验证渲染负载，不用于评估真实通关难度。每轮预热约 1.2 秒，再采样约 6 秒；帧间隔使用原始帧时间戳，CPU 耗时包含更新与提交渲染，不代表 GPU 本身的执行耗时。

| 条件 | 平均整帧 CPU 耗时 | 整帧 CPU P95 | 帧间隔 P95 | 实测帧率 |
| --- | --- | --- | --- | --- |
| 基线 | 7.41 ms | 7.80 ms | 16.80 ms | 60.0 FPS |
| 本轮修改后 | 2.58 ms | 3.70 ms | 17.50 ms | 60.0 FPS |
| 基线，CPU 4 倍降速 | 31.13 ms | 32.50 ms | 34.20 ms | 31.3 FPS |
| 修改后，CPU 4 倍降速 | 1.89 ms | 3.10 ms | 17.60 ms | 60.0 FPS |

本机常规采样的平均整帧 CPU 耗时约降低 65%，帧率两边均约为 60 FPS。新增分部件动画使更新阶段开销增加，纹理缓存和减少几何重画使整体耗时下降。CPU 降速测试为短时浏览器模拟，包含 JIT 预热影响，不能代替真机、温控或长时间稳定性验收。
